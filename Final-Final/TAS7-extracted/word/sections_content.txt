SECTION: PDPA (Paragraph 100)
====================================================================================================

[Paragraph 100]
การวิจัยนี้พัฒนาโปรแกรมยืนยันตัวตนแบบบูรณาการระหว่างระบบงานตามมาตรฐาน PDPA โดยใช้สถาปัตยกรรมโมโนลิธ (Monolithic Architecture) เพื่อรองรับการยืนยันตัวตนที่ปลอดภัยและมีความซับซ้อนในโค้ดเบสเดียว ระบบที่พัฒนาขึ้นรองรับ OAuth 2.0 และ OpenID Connect พร้อมการใช้งาน PKCE (Proof Key for Code Exchange) เพื่อเพิ่มความปลอดภัยในการแลกเปลี่ยนข้อมูล

[Paragraph 101]
ระบบประกอบด้วยโมดูลหลัก 3 โมดูลในโค้ดเบสเดียว ได้แก่ 1) โมดูลยืนยันตัวตน (Authentication Module) ซึ่งรวมการจัดการเซสชันไว้ด้วย 2) โมดูล OAuth (OAuth Module) และ 3) โมดูลจัดการผู้ใช้ (User Module) นอกจากนี้ยังมี Shared Services ได้แก่ Security Audit Service และ Session Service การสื่อสารระหว่างโมดูลใช้ function calls โดยตรง และใช้ Apache Kafka สำหรับการบันทึกข้อมูลแบบกระจาย

[Paragraph 102]
การทดสอบระบบพบว่าระบบสามารถทำงานได้ตามฟังก์ชันที่กำหนดไว้ทั้งหมด ได้แก่ การลงทะเบียน การเข้าสู่ระบบ การเข้าสู่ระบบผ่านผู้ให้บริการภายนอก (Google, GitHub) การจัดการเซสชัน และการจัดการความยินยอมตาม PDPA ผลการทดสอบความพึงพอใจของผู้ใช้งานพบว่าระบบได้รับคะแนนความพึงพอใจเฉลี่ย 4.70 จาก 5 คะแนน

[Paragraph 103]
คำสำคัญ: การยืนยันตัวตน, OAuth 2.0, โมโนลิธ, PDPA, ความปลอดภัย

Abstract

[Paragraph 116]
This research develops an integrated authentication system compliant with PDPA standards using Monolithic Architecture to support secure and flexible authentication within a single codebase. The developed system supports OAuth 2.0 and OpenID Connect with PKCE (Proof Key for Code Exchange) implementation for enhanced security in data exchange.

[Paragraph 117]
The system consists of 5 main modules in a single codebase: 1) Authentication Module, 2) OAuth Module, 3) User Module, 4) Session Module, and 5) Security Audit Module. Inter-module communication uses direct function calls and Apache Kafka for distributed logging.

[Paragraph 118]
System testing results show that the system can perform all specified functions including registration, login, external provider login (Google, GitHub), session management, and PDPA consent management. User satisfaction testing results show an average satisfaction score of 4.70 out of 5.

[Paragraph 119]
Keywords: Authentication, OAuth 2.0, Monolith, PDPA, Security

2.7 OpenID Connect (OIDC)

[Paragraph 315]
OIDC เป็น identity layer บน OAuth 2.0 จาก OpenID Foundation ช่วยให้ client ตรวจสอบตัวตนผู้ใช้ได้ นอกเหนือจาก authorization ปกติ โดยเพิ่ม ID Token (JWT ที่มี identity claims)

[Paragraph 316]


[Paragraph 317]
OIDC Claims ที่ระบบรองรับ: sub (user ID), email, name, username, role, email_verified

[Paragraph 318]


[Paragraph 319]
Endpoints ที่ระบบ implement ตาม OIDC spec //fact check

[Paragraph 320]
- GET /.well-known/openid-configuration - OIDC Discovery Document (auto-configuration)

[Paragraph 321]
- GET /.well-known/jwks.json - JSON Web Key Set สำหรับตรวจสอบ signature

[Paragraph 322]
- GET /api/oauth/userinfo - ดึง user claims ด้วย Bearer token

[Paragraph 323]
- GET /api/auth/oauth-session - สร้าง session หลัง OAuth login redirect

[Paragraph 324]


[Paragraph 325]
Scopes ที่รองรับ: openid, profile, email

[Paragraph 326]
ในระบบนี้ใช้ OIDC + Authorization Code Flow + PKCE เพื่อความปลอดภัยสูงสุดตามมาตรฐาน 2024

2.8 งานวิจัยที่เกี่ยวข้อง //fact check

[Paragraph 330]


[Paragraph 331]
2.8.1 Fett, Küsters & Schmitz (2016) — การวิเคราะห์ความปลอดภัย OAuth 2.0 เชิงคณิตศาสตร์

[Paragraph 332]
Fett et al. (2016) ได้ทำการวิเคราะห์ความปลอดภัยเชิงคณิตศาสตร์อย่างเป็นทางการสำหรับ OAuth 2.0 ทั้ง 4 grant types โดยใช้ web attacker model ที่ครอบคลุม ผลการศึกษาพิสูจน์ว่า authorization code flow เมื่อใช้ร่วมกับ HTTPS และการตรวจสอบ state parameter สามารถรับประกันความปลอดภัยด้าน authorization และ session integrity ได้อย่างแข็งแกร่ง นอกจากนี้ยังพิสูจน์ว่า implicit flow มีความปลอดภัยต่ำกว่าเนื่องจาก access token ถูกเปิดเผยใน URL fragment ระบบ TAS ได้นำ authorization code flow มาใช้แต่เพียงอย่างเดียวและเพิ่ม PKCE (S256) เพื่อป้องกัน code interception attacks ตามข้อพิสูจน์ของ Fett et al. [16]

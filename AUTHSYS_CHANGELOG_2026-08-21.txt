วันที่: 2026-08-21

====================
แก้ไข (FIXED)
====================

1. OAuth consent / grant lifecycle
- เพิ่ม grantId ให้ Consent และ AuthorizationCode
- revoke consent เก็บ tombstone และทำให้ access/refresh token เดิมใช้ไม่ได้
- ตรวจ active User, active OAuth client และ active consent grant ตอนใช้ token
- ลบ OAuth client หรือ deactivate user แล้ว revoke grant ที่เกี่ยวข้อง
- Allow ซ้ำด้วย scope เดิมขณะ grant ยัง active จะคง grant เดิม ไม่ทำให้ token ที่ออกไปแล้วเสียโดยไม่คาดคิด
- refresh token ใช้ได้เฉพาะเมื่อมี offline_access และมีการ rotate/blacklist

2. CSRF
- แก้ global middleware ให้รองรับ csrf_token ที่ consent page ส่งใน JSON body
- controller และ middleware ตรวจ signed token ชุดเดียวกัน
- consent flow บน HTTPS ผ่านจริง ไม่ติด 403 จาก middleware ก่อนถึง controller

3. Session / startup / security
- production startup/readiness บังคับ MongoDB และ Redis session readiness
- active session re-fetch User และปฏิเสธ account ที่ inactive
- เปลี่ยน malformed login email object จาก 500 เป็น validation 400
- first-party browser ใช้ HttpOnly session cookie; ไม่เก็บ bearer token ใน localStorage/sessionStorage

4. Docker / deployment portability
- production images ใช้ Node 20-alpine, รันด้วย non-root user และติดตั้ง production dependencies ด้วย npm ci --omit=dev
- client-1 ใช้ HTTPS callback และเก็บ OAuth token ใน server-side session
- client-2 Compose env เป็น optional ตอน render base config แต่ production ต้องกำหนด HTTPS callback จริง
- deploy ใช้ Docker Compose บน VPS ได้โดยไม่ผูก Alibaba API และไม่ลบ named volumes

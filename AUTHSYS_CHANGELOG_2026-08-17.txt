====================
แก้ไข (CHANGED / FIXED)
====================

1. Client 1 authentication
- เปลี่ยนเป็น session-cookie-only
- ไม่ส่ง accessToken ผ่าน /api/session
- ไม่ให้ frontend อ่านหรือ refresh access token โดยตรง
- เก็บ OAuth tokens ไว้ใน server-side session เท่านั้น
- protected pages: dashboard, products, profile
- ป้องกัน static HTML ไม่ให้ bypass auth route
- แก้ cart mockup ให้ทำงานด้วย localStorage

2. OAuth role separation
- role ภายใน AuthSys ยังใช้ตรวจ admin access ได้
- role จะไม่ถูกส่งออกไปใน OAuth token หรือ UserInfo
- OAuth app owner แยกจาก end-user ที่ login เข้า app
- ผู้ใช้ AuthSys คนใดก็ได้สามารถ authorize OAuth app ที่ active ได้

3. Role-based access control
- Admin เท่านั้นที่เข้าถึง analytics
- Admin เท่านั้นที่เข้าถึง monitoring และ system health
- Admin เท่านั้นที่เข้าถึง audit/security logs
- Admin เท่านั้นที่ดู system-wide statistics
- เปลี่ยน /api/dashboard/logs/stats ให้เป็น admin-only
- เปลี่ยน /api/dashboard/ ให้เป็น admin-only
- user routes ยังคงดูได้เฉพาะข้อมูลของ user ที่ login อยู่
- OAuth client management ยังคงจำกัดตาม owner ของ app

4. Consent / security
- จำกัด consent เป็น Allow หรือ Deny ไม่มี partial consent
- เพิ่ม revoke consent
- เพิ่ม cookie consent CSRF protection
- ตรวจ exact redirect URI ทุกครั้งก่อนออก authorization code
- ป้องกัน bearer token ใน query string
- ปิด legacy social callback ที่รับ token ผ่าน URL

5. Admin UI
- แทนที่หน้า Admin เดิมที่ซับซ้อนและมีข้อมูลตัวอย่าง
- ใช้หน้า Admin แบบ simple สำหรับ personal project
- API guard ยังคงทำงานฝั่ง server ด้วย authorizeRole('admin')

=== Developer hardening follow-up: 2026-08-20 ===

- Web register/login now return only safe session/user data; bearer credentials remain on the explicit API compatibility login route or OAuth token endpoint.
- First-party browser pages use the Secure, HttpOnly session cookie and no longer refresh/store access or refresh tokens in localStorage/sessionStorage.
- Remember me now maps to a documented 30-day web session; default web session remains 1 hour.
- Anonymous cookie choices are queued locally and synchronized after the user becomes authenticated.
- OAuth requested scopes must be registered by the client; offline_access is explicit and is not implicit.
- Cookie-authenticated API mutations require a same-origin signal or CSRF token.
- OAuth public error descriptions were made stable and internal error details remain server-side.
- Client-1 no longer requests unregistered offline_access.
- Production operations must remove the stale public Kafka UI port 8080 before wider access.
